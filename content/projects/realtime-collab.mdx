## Executive Overview

Collaborative digital whiteboards and design tools require uncompromising rendering performance while seamlessly synchronizing concurrent edits from dozens of remote participants across unreliable network connections.

Traditional DOM-based canvases or naive WebSocket message broadcasting suffer from frame-drops during complex pan/zoom operations and catastrophic edit collisions when users work offline or on high-latency mobile networks.

We engineered a **local-first collaborative canvas engine** from scratch using WebGL batching, Yjs Conflict-free Replicated Data Types (CRDTs), and off-thread state indexing inside Web Workers.

### Core Design Decisions

1. **Local-First Conflict Resolution (CRDTs):**
   - Implemented Yjs state trees representing shapes, vectors, freehand strokes, and comments.
   - Edits are committed immediately to the local client state and serialized as compact binary diffs broadcast asynchronously to peers.
   - Mathematical convergence guarantees identical state without requiring lock management or server arbitration.

2. **Off-Thread Computation with Web Workers:**
   - Isolated graph parsing, spatial index querying (2D R-Tree), and CRDT delta merging onto background workers.
   - The main UI thread remains completely unblocked, guaranteeing jitter-free 60/120Hz scrolling, zooming, and trackpad gestures.

3. **Hardware-Accelerated WebGL Viewport:**
   - Replaced SVG/HTML5 2D canvas with instanced WebGL drawing routines.
   - Implemented dynamic Level of Detail (LoD) downsampling for distant viewports, rendering up to 100,000 active scene elements effortlessly.

## Complex Challenges Solved

### Handling Concurrent Freehand Drawing at Scale
Continuous pen and brush input generates hundreds of coordinates per second. Broadcasting raw coordinates flooded WebSocket buffers and bloated memory history.
- **Solution:** Designed an adaptive Douglas-Peucker bezier curve simplification pipeline running directly on pointer move. Points are batched and encoded using delta-varint compression before CRDT transaction dispatch.
- **Outcome:** Bandwidth consumption dropped by **78%** without any discernible degradation in stroke smoothness.

### Real-Time Presence & Ephemeral Cursors
Syncing remote cursors through persistent CRDT structures created unnecessary historical tombstone overhead.
- **Solution:** Separated the sync layer into two distinct channels:
  - *Durable State:* Yjs binary document sync over WebSockets.
  - *Ephemeral State:* Lightweight binary WebRTC DataChannels for cursor coordinates and selection halos, with automatic interpolation.
